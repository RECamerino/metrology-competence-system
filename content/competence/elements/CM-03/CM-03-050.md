summary: >-
  Obtaining the sensitivity coefficients for a budget by differentiating the
  measurement model, evaluating the derivatives at the estimates, and carrying
  the units they convert. The differentiation is undergraduate calculus and an
  AI performs it instantly; what is assessed is a coefficient set a reviewer
  can check against the model, produced at the operating point the records
  describe. Two structures defeat careless work — an input appearing in more
  than one place, and a derivative that changes sign inside the working range —
  and both produce a budget that looks entirely well formed.

Notes for assessors and item authors. The subject is explained in `BOK-0003`
§s02 — do not restate it here.

**This is a `skill` element and the anchors are performance, because the
calculus is not the competence.** Differentiating a closed-form expression is
lookupable, an AI does it faster and more reliably than a person, and
assessment is open-resource by design. What is assessed is the coefficient set
in a budget the candidate produced: whether it was evaluated at the right
point, whether the units convert, and whether a reviewer holding the model can
check it line by line.

**Not bound at L1, deliberately, and the binding file says why.** With every
value supplied including the coefficients there is nothing about deriving them
left to observe. The coverage report will show L1 as a gap, which is accurate —
the level needs a narrower item shape than budget construction, and padding one
in would inflate the reuse figure while assessing nothing. The L1 anchor above
exists because the level is attainable and needs a definition, not because an
item currently reaches it.

**The levels move on what the candidate had to supply.** At L1 the model is
given and so is the input to differentiate. At L2 they differentiate the whole
model into a table that already exists. At L3 there is no table and no model
written out — only records — and the operating point becomes theirs to
establish. At L4 the model contains a structure that punishes the obvious
derivation.

**Where candidates fail, in order of frequency.** Assuming a coefficient of one
because the input and output happen to share units, which is correct by
accident until the model changes to a ratio. Differentiating only the first
occurrence of an input that appears twice, where the true derivative is the sum
of both contributions and the effects may partly cancel — the result is wrong
in magnitude and sometimes in sign. Evaluating at a nominal rather than at the
operating point the records describe, which matters exactly where the
derivative is not constant over the range. Losing the exponent on a power term,
which is a factor-of-two error in the commonest case. And dropping units, so
the contribution arrives in the units of the input rather than the measurand
and nothing in the table shows it.

**Boundary with `CM-03-051`, and the pair is what makes both honest.** This
element is the model that *can* be differentiated. Where it cannot — a routine,
a lookup, a fitted surface — the coefficient is estimated numerically and that
is `CM-03-051`. The generator parameter deciding whether a closed form exists
is what separates the two bindings; without it both would be budget
construction wearing different labels.

**The ceiling is 4 and should stay there.** An L5 would have to describe expert
practice in differentiating a function, and there is none. The genuinely expert
work adjacent to this is knowing when the derivative stops representing the
model at all, which is `CM-03-056` and carries its own ceiling of 5.
